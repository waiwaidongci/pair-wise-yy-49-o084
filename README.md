# 高校课程标准映射与课程改革审阅平台

面向教研人员、课程负责人和院系审阅人的课程图谱平台，支持培养目标、毕业要求、课程单元、教学活动、考核任务映射，以及有向图检查、覆盖矩阵、拖拽连边、自动保存、批量审核和课程地图导出。

## 技术栈

SvelteKit + Skeleton UI + Svelte stores + SvelteKit Form Actions + TanStack Query + Zod + Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev
```

访问 `http://localhost:62049`，生产构建使用 `npm run build`。

## 核心工作流

- 在培养目标、毕业要求、课程、单元和考核之间建立有向映射。
- 自动检查前置关系、覆盖缺口、重复映射和不完整考核证据。
- 课程负责人提交修订，院系审阅人逐条退回、附议或要求补充证据。
- 比较版本覆盖变化，恢复草稿并导出专业课程地图。

## 课程对账中心（/reconcile）

教务系统每周推送课程目录与先修关系，专业课程图谱里的人工映射会因此过时。对账中心把外部目录、本地映射与毕业要求覆盖结论接成一次可续作的对账：

- **幂等推送**：推送携带课程编号、学期与修订号，键为 `课程编号|学期|修订号`；同一修订重复推送沿用第一次结果，不触发失效重算。
- **失效重算**：新修订到达且先修关系变化时，相关课程的派生映射与覆盖结论立即失效并重算为 `stale`；人工调整值进入「已暂停」队列待复核，不能悄悄覆盖来源变化。
- **乐观并发确认**：确认携带载入时的课程版本，只有基准版本一致的一方写入；基准不一致（他人已先写入或来源已更新）的落败内容留作「待核」，可采纳或驳回。页面提供「模拟双人同时提交」演示。
- **批次断点续跑**：批次逐课程写入并保存检查点；写入失败后从最后完成课程继续，已确认课程跳过不重复。可注入一次性写入失败演示恢复流程。
- **未编号兼容**：缺少外部编号的已有数据先兼容保留为 `unlinked`，补齐编号后即接回对账并取台账中的最新修订。

对账引擎为 `src/lib/reconcile/engine.ts` 纯函数，服务端单例在 `src/lib/reconcile/server-state.ts`，API 位于 `/api/catalog/push` 与 `/api/reconcile/*`。
